# CheckFreq Robustness Study

This experiment evaluates the CheckWork claim that CheckFreq-style checkpointing keeps substantially less checkpoint cost on the critical path than synchronous checkpointing across a broader design space.

## Scope

The sweep varies model architecture, checkpoint cadence, checkpoint size, storage tier, and network topology. Each non-baseline cell is generated twice: once with `checkfreq_like` and once with `sync`.

Default full-run axes:

- Models: `bert`, `gpt_small`, `gpt_medium`.
- Checkpoint cadence: `10`, `25`, `50`, and `100` iterations.
- Per-rank checkpoint size: `500`, `2000`, and `5000` MB.
- Storage tiers: `sata_slow`, `nvme_std`, and `nvme_fast`.
- Networks: `network_8_balanced`, `network_8_fast`, `network_8_bw100`, and `network_8_ring`.

Snapshot and persist durations are derived from checkpoint bytes and the selected storage bandwidths rather than being hand-tuned.

## Running

```bash
source ../../chakra_env/bin/activate
python3 run_robustness.py --quick      # smoke test
python3 run_robustness.py              # full sweep
python3 run_robustness.py --skip-gen   # reuse generated traces
python3 run_robustness.py --local      # no ASTRA-sim Docker dependency
python3 plot_results.py
```

The ASTRA-sim path expects a Docker image named `astra-sim:latest`. The `--local` mode is a lightweight topological fallback for sanity checks.

## Outputs

- `results/runs.csv` and `results/runs.json` contain one row per simulation.
- `results/summary.csv` contains paired CheckFreq-vs-sync overhead comparisons.
- `results/plots/` is generated by `plot_results.py` and ignored by Git.
- `results/timeline_logs/` contains raw simulator output and is ignored by Git.
